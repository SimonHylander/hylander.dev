## Decisions

I used the strangler fig pattern. The new client took over one route at a time, and the monolith kept serving the rest.

<BuildDiagram diagram={byggdagbokenDiagram}>
<DiagramStep>

**The monolith.** Web traffic went through CloudFront to the monolith. It ran PHP on the server and Angular.js in the browser.

</DiagramStep>
<DiagramStep>

**Route-level canaries.** A CloudFront Function sends a percentage of each migrated route's traffic to the new Next.js web client. The rest stays on the monolith.

</DiagramStep>
<DiagramStep>

**A backend-for-frontend.** The native apps talk to a Node.js BFF, which aggregates their data across the microservices.

</DiagramStep>
<DiagramStep>

**One sign-in.** I moved sign-in to OAuth2 and OpenID Connect with the Authorization Code flow and PKCE. Redis holds the short-lived tokens.

</DiagramStep>
</BuildDiagram>
